# 热潮之后，AI 产品靠什么留下来

文／Oratis

2022 年 11 月 30 日，ChatGPT 把人工智能带到了普通人的对话框里。此后，模型一次次刷新能力边界，产品和资本市场也不断扩大对未来的想象。今天，当 Agent 开始替人执行任务，新的期待又在聚集。Gartner 在 2026 年讨论 Agentic AI 时，将其描述为热度处于高峰、应用仍在早期的技术。不同赛道各有节奏，但高峰上的团队都会遇到同一个问题：当新鲜感过去，用户为什么还要回来？[ChatGPT 发布记录](https://openai.com/index/chatgpt/) · [Gartner 对 Agentic AI 的判断](https://www.gartner.com/en/podcasts/thinkcast/the-2026-hype-cycle-for-agentic-ai-what-leaders-need-to-know)

期望膨胀期也会诞生好产品。行业已经形成需求，模型跨过可用门槛，团队又能把能力变成顺手的体验，天时、地利、人和就可能同时到位。Seedance 让视频创作的结果可以被直接展示，Claude Code 则进入开发者每天使用的工作环境。成功会引发传播，增长又让更远的承诺得到关注，从一个好用的助手，延伸到改变工作，再延伸到 AGI。[Seedance 2.0 发布说明](https://seed.bytedance.com/zh/blog/official-launch-of-seedance-2-0) · [Claude Code 产品与增长记录](https://www.anthropic.com/news/anthropic-acquires-bun-as-claude-code-reaches-usd1b-milestone)

这种“讲故事、验证增长、延伸故事”的循环，也容易奖励过度承诺。我们做逗逗 AI 时，同样遇到过这个问题。当演示足够惊艳，团队很容易把一次成功理解为普遍能力，再把尚待解决的问题放进下一个版本。用户却会在每一次真实使用中检验承诺。我的判断是，只凭技术新颖性获得耐心的阶段正在结束。进入低谷后，产品是否持续改善、每次交付是否有毛利，会变得格外重要。

中国的开放模型正在加快这一转折。以往，前沿实验室展示突破，到市场出现可用的替代方案，中间常有一段时间差。DeepSeek、Qwen 等团队提供可下载、可部署的模型，让应用公司能够更早用自己的任务比较效果，并探索更适合自身规模的成本结构。围绕尖端算力积累能力，与依靠开放权重扩散能力，是两种相互影响的路径。国家之间、企业之间都存在交叉，而应用团队真正感受到的变化，是替代选择来得更快，能力稀缺所支撑的溢价更早接受检验。[DeepSeek-R1](https://github.com/deepseek-ai/DeepSeek-R1) · [Qwen3 开放权重说明](https://qwenlm.github.io/blog/qwen3/)

能源与芯片的分布又让这种竞争更复杂。能源研究院的同一统计表显示，2024 年中国发电量约为 10087 太瓦时，美国约为 4635 太瓦时，中国达到美国的 2.18 倍。全国发电总量还需要经过电网、选址和设备，才能成为数据中心可用的电力。先进芯片的可获得性同样会限制算力扩张。供电充足的地区要提高芯片和系统效率，拥有前沿芯片的企业也要解决接电与运行成本，双方都在寻找资源约束下的出路。[能源研究院《世界能源统计年鉴》，发电量表](https://www.energyinst.org/__data/assets/pdf_file/0007/1658077/Statistical-Review-of-World-Energy.pdf)

与此同时，AI 的物理成本无法靠叙事消除。国际能源署在 2026 年更新的预测中，预计全球数据中心用电量将由 2025 年的 485 太瓦时增至 2030 年的约 950 太瓦时，AI 专用数据中心增长更快。这个口径覆盖数据中心整体。单次简单任务的能效正在改善，但视频生成、长程推理和 Agent 工作又带来更高强度的需求。电网接入、供电和芯片供应的约束，最终都会落到一次任务的价格、延迟和可用性上。[国际能源署《Key Questions on Energy and AI》](https://www.iea.org/reports/key-questions-on-energy-and-ai/executive-summary)

模型越来越强，反而让应用公司面对一个悖论。模型能力本身可以构成完整体验，也可能吞掉应用曾经提供的功能。Andrej Karpathy 用 Software 1.0、2.0、3.0 描绘了从手写代码、训练权重，到通过上下文和自然语言编程的变化。他举的 MenuGen 例子很直观：原先要识别菜单、生成菜品图片、组织界面的一套应用，后来可以让多模态模型直接把菜单照片变成配图菜单。用户需要的变换被模型完成，周围的软件便失去了一部分必要性。[Karpathy 在 Sequoia Ascent 2026 的访谈](https://www.youtube.com/watch?v=96jN2OCOfLs)

应用团队因此需要问得更具体。哪一小群人正在为什么结果付钱？他们愿意让 Agent 接手其中哪一步？先把一个高价值的小任务做透，比在通用模型旁边堆更多入口更容易建立关系。产品必须贴合模型的能力和演进方向，同时拥有自己的交付标准、获客方式和收入来源。我更关心三项积累：选择模型的能力，组织用户资产和上下文的能力，以及让任务可靠落地的工具。

LLM 正在走向多步规划与执行，视觉模型也在连接原先分开的能力。BAGEL 将多模态理解和图像生成纳入统一模型，并展示了图像编辑能力。对内容产品，我把这种进展理解为一个可以反复运行的过程，先理解意图，再生成结果，根据用户反馈继续编辑。应用需要在这次循环中积累角色、素材和选择，让模型每次进步都能变成用户可感知的改善。[BAGEL 官方研究与实现](https://github.com/ByteDance-Seed/Bagel)

模型选型始终面对成本、速度、效果之间的取舍。一个请求可以更快返回，也可以多思考几轮提高成功率，或者在低负载时用自有硬件批量处理。选择取决于用户正在做什么。遇到故障时，用户购买的服务能否由另一个模型继续交付，是应用独立性的一次检验。Model router 因而要同时理解用户价值、技术条件和成本预算。便宜模型需要反复返工时，便宜的单次调用也会变成昂贵的最终结果。

我相信现有模型已经留下很大的产品空间。对于目标明确、有工具可调用、结果可验收的常规子任务，可以从约 300 亿参数的模型开始测试，并通过蒸馏进一步探索更小的部署规模。能否胜任，要由真实任务决定。团队应比较成功交付的成本、延迟和人工接管率，再选择自有算力、托管服务或 API。高效使用模型，体现在每个被用户接受的结果上，也体现在峰值容量、缓存、批处理和失败恢复这些日常工程里。[Qwen3 技术报告](https://arxiv.org/abs/2505.09388)

更难替代的积累往往在数据中。通用模型已经学过许多公开知识，却未必见过客户昨天的修改、玩家上一局的犹豫，或创作者拒绝某个镜头的原因。我尤其重视两类数据：公共训练材料尚未覆盖的真实经历，以及用户愿意授权产品使用的个人上下文。数据质量、覆盖范围和反馈方式共同决定学习价值。一段没有结果标记的长对话，未必比一句解释失败原因的纠正更有帮助。

这些材料还需要组织起来。Data 保存任务、选择与结果，harness 管理执行、重试和验收，context 则在当下挑出模型真正需要的信息。更多记录会增加检索和计算成本，也可能让重要信息淹没在细节里。能否把恰当的信息送到恰当的一次决策中，决定了用户积累的历史能否变成更好的体验。[Anthropic 的上下文工程实践](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

Agent 的工具体系也在发生变化。Connector 把账号、业务系统和资料接进来，skill 保存一类任务的操作方法，tool 执行具体动作，再由本地、云端或边缘的运行环境完成工作并回报结果。Manus 把应用连接、MCP 和 API 做成用户可配置的入口，Muse 则把连接器、技能和运行任务的云端计算机组合起来。产品由此能够围绕用户已有的资料组织工作，每个连接和动作也都需要明确的权限与结果记录。[Manus Connectors](https://www.manus.im/features/connectors) · [Muse 的连接器、技能与执行环境](https://muse.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)

再往前一步，软件会在使用中长出差异。Claude Code 的 mods 允许用户修改提示、工具行为和界面，也可以让 Claude 编写并加载这些修改。DeepSeek Harness 则提供可组合的插件体系。我预期，不同人的 Agent 会逐渐形成不同的能力组合、偏好和操作路径。设计者需要交付能够演变的能力、边界与反馈机制，并持续检验这种变化是否真的帮用户把事情做好。[Claude Code mods](https://claude.com/resources/articles/claude-code-mods) · [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)

陪伴和内容体现了两种不同的积累方向。逗逗 AI、HakkoAI 围绕共同经历组织体验。玩家刚输掉一局，AI 看懂了画面，还要知道他此刻想听攻略、想听安慰，还是希望安静一会儿。相同画面，换一段历史，恰当的回应就可能完全不同。模型层需要快速、灵活、稳定地跟进进展，工具可以保持精简，关系的连续性则要靠准确的上下文、可纠正的记忆和对用户意愿的尊重。[逗逗 AI 产品说明](https://www.magicneko.com/article/2/) · [HakkoAI 产品说明](https://www.hakko.ai/)

内容产品要回答的核心问题是，究竟生成什么。一次角色扮演可以停留在文字对话里，真正令人愿意继续消费的娱乐内容，还要有节奏、悬念、共鸣和获得感。文字已经能承载这些价值，多模态又为视频和互动打开了空间。Cuddler 提供角色聊天、剧集、分支故事和创作入口，我们希望进一步连接视频创作和视频消费，让观看中的选择成为下一次创作的起点。[Cuddler 产品说明](https://cuddler.ai/docs/what-is-cuddler)

这条路需要面对产业链的挤压。Seedance、Kling 等模型提供生成能力，OpenArt、Tapnow 等工具组织创作流程，红果、抖音等平台连接内容与观众。当模型增加编辑能力、消费平台补齐制作入口，中间工具就必须证明自己创造的额外价值。一个可见功能越来越容易被模仿，稳定的角色资产、创作者关系、观众偏好和交易安排却需要长期经营。我的选择是把工具放进创作、观看、付费和反馈的完整过程里，让每一次生成更接近一份有人愿意消费的内容。

讨论商业化，最终要回到钱从哪里来。我会优先找已经存在付费行为的细分场景，并设定一个足够高的切换门槛，例如让某项工作的效率改善十倍。这个倍数是筛选目标，需要通过质量、时间和成本一起验证。通用游戏攻略有大量免费替代，直接收费需要更具体的价值。客服已经有明确的人力与服务预算，但 Agent 能接走多少工作，也要算上复杂问题、人工升级和服务责任。付费人群可以很小，任务可以很窄，购买理由必须具体。

毛利也会被细节改变。创作者只想改最后一个镜头，系统却重生成整部短片，用户多等了一轮，团队也多付了一轮。把可保留的部分锁住，把返工控制在失败的位置，同时改善体验和成本。运营同样如此。每段客户对话都可能包含一次没有被理解的需求、一项失约或一个可挽回的关系。认真回应，确认问题真正解决，再把重复问题反馈到产品中，才能让增长成为可持续的业务。

组织需要跟着任务变化。AI 原生团队可以先说清交付结果、时间约束、数据接口和资源预算，再匹配有能力负责的人与 Agent。任务完成后，新的组合继续形成。这要求管理者了解人的判断力、学习速度和协作方式，也要求每件事始终有人承担最终责任。对个人来说，AI 加快执行之后，时间、注意力和精力更容易错位。日程空着却无法专注，与持续处理消息却没有推进重要工作，都需要主动调整。

工作中最值得保留的专注，往往用于确定问题。“分析一下流失”可以产生一大堆解释，“第一次生成失败后，哪一步最让付费用户放弃”则指向可观察的行为，也连接着团队这周能做的改变。这样的问题来自对客户处境的了解。独特的生活体验，让人注意到不同的细节，也形成不同的审美判断，此处为什么需要留白，一句准确的话为什么仍显得冒犯，一个结尾为什么让人愿意停留。Agent 越擅长执行，人越需要接触现场，在经历中形成判断。庄子说，“言者所以在意，得意而忘言”。语言、样本和工具能够传递大量经验，人的参与还体现在为这些经验赋予意义，并为选择承担后果。[《庄子·外物》](https://ctext.org/zhuangzi/what-comes-from-without/zh)

我们离 AGI 还有多远，我没有可信的倒计时。我怀疑今天的 Transformer 能否直接成为最终架构，也期待研究更多关注单位能量能够完成多少可靠的智能任务。自我改进会扩大能力来源，但系统仍需要能判断好坏的反馈。AlphaGo Zero 可以通过自我对弈获得经历，棋局胜负为学习提供了明确结果。开放世界里的迟到反馈、罕见失败和专家纠错，往往更难得到。找到别人尚未拥有的数据，把最难获得的经历记录成可学习的反馈，仍然值得长期投入。[AlphaGo Zero 原始研究](https://www.nature.com/articles/nature24270)

热度退去时，宏大的想象会接受具体生活的检验。我们可以承认能力的边界，也可以继续把一段陪伴、一份作品、一个客户的问题做得更好。罗曼·罗兰所说的英雄主义，是看清世界的样子，并且爱它。对于今天的 AI 创业者，这份热爱可以落实到每天的工作中，兑现一次承诺，理解一位客户，交付一个值得留下的结果。[罗曼·罗兰原文影印本](https://doi.org/10.3931/e-rara-69089)
